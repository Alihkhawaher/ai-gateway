# v2.16.0 — 2026-11-18

## Fixed
- **The web chat no longer loses an answer when its connection drops.** The bundled web UI cancels a stream when you come back to its tab after more than 3 seconds without output (a long prompt, slow thinking) and asks the server to replay it. The gateway had no replay, so the request fell through to another endpoint and the page showed "Stream connection lost and could not be resumed", while the model kept generating for nobody.
  - **Keep-alives:** while the web UI waits, the gateway sends an SSE comment (`: keep-alive`) after each second without output, so the page never sees a quiet stream. Readers ignore comments.
  - **Replay:** `GET /v1/stream?conv_id=…&from=<bytes>` sends the answer from that byte and follows it live to its end. When the browser drops, the gateway keeps reading the model's reply so it isn't lost; if the page doesn't come back within 30 seconds (you pressed Stop), the gateway stops reading and the model is let go.
  - **Lookup:** `POST /v1/streams/lookup` tells the web UI which of its chats have an answer running or just finished, so a reloaded page reattaches to it.
  - Only requests carrying the web UI's `X-Conversation-Id` header take this path. Every other client gets the stream byte for byte, as before.
  - The answer is kept in memory only, never on disk or in the log, readable only from the address that asked, and forgotten 5 minutes after it ends.
