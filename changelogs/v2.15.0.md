# v2.15.0 — 2026-11-12

## Added
- **Access keys: lock the gateway so only your apps can use it.** Out of the box anyone on the network can use the gateway's models and cloud credit. Add keys under **Access Keys** in Settings (**+ New key** makes a strong one), or `"access_keys": [...]` in `config.json`, and every API request must send one as `Authorization: Bearer`, `x-api-key` or `api-key`. Off by default.
  - A missing or wrong key gets `401` with the OpenAI code `invalid_api_key`. The web chat page asks for the key on that answer and remembers it, so only its own files load without one.
  - The key never goes upstream: endpoints get their own `api_key`, and `/cors-proxy` passes on only the MCP server's own headers.
  - Refusals are logged once a minute per address, never with the key. Keys shorter than 16 characters are ignored.
  - The main screen shows `Access : API key needed (N keys)` or `open, no key needed`.

## Changed
- The README is shorter to read: each feature is said in a few lines, and the technical details fold away under them. New screenshots, from a demo with made-up traffic, show the dashboard, the Heal column and the endpoint options.
- The endpoint dialog's checkbox reads **Compact early (say 'full' at 90%)**; the longer label was cut off.
