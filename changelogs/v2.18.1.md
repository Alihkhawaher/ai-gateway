# v2.18.1 — 2026-11-19

## Fixed
- **A llama-server no longer answers for a model it doesn't have loaded.** A llama-server serves one model, whatever a request names. When the P40 launcher switches models on the same port, an app still set to the previous model used to get replies from the new one, with no error.
  - Before a chat, the gateway now asks the server which model it has loaded (`/props`: the GGUF file name and `--alias`, cached for 5 seconds).
  - A request naming another model gets `404 model_not_found`, naming the loaded model's ID so the app can switch.
  - When the server can't be asked, the request goes through as before.

## Tests
- `LoadedModelCheckTests` (3):
  - the loaded model is served, by file name or alias;
  - another model is refused with the loaded one's name, and the server never sees it;
  - an unreadable `/props` lets the request through.
