# v2.7.0 — 2026-11-06

## Added
- **Live stats on the console's main screen.** A new **Live** panel beside the endpoint list shows, every second, what the engine is doing (reading with progress and time left, generating with speed, idle, not loaded), the held chat against the context limit, cache hit rates, GPU load, temperature and VRAM, and today's totals.
- **Full dashboard on `d`:**
  - **Engine:** model, state, chat size, requests in flight and queued.
  - **Cache:** prompt tokens reused, expert hit rate, drafts kept, chats parked in RAM, how each request found its chat (kept, restored, new), swap times, and an estimate of the reading time saved.
  - **Speed:** output speed with a 60-second graph, reading speed, time to first token (median and p95), requests per minute, tokens per day.
  - **Hardware:** GPU, temperature, power, VRAM, PCIe, CPU, RAM and disk.
  - **Totals:** this run, today and all time.
  - **Saved chats, Endpoints, Models, Apps and Recent requests** tables.
- **Works with any endpoint.** Tokens and speed are read from responses as they pass, in the OpenAI, Anthropic, DeepSeek and Responses API formats, and from llama.cpp's `timings`. Engine, hardware, expert and draft figures need an engine that publishes `/metrics`, which today means Strata.
- **Each request is credited to its app**, from `X-Title`, the referer or the `User-Agent`.
- **`GET /stats`** returns the same numbers as JSON.
- **All-time totals survive a restart**, in `gateway-stats.json` (gitignored): counts and names only, with daily rows for 30 days.

## Changed
- **Log lines say more.** A generation request now logs its tokens, cached share, speed and swap, for example `→ up [200]  100 in (75% cached) · 20 out`.
- **The main screen has two columns** in a wide window, and stacks in a narrow one.
- **Saved chats remember which app they came from**, and `GET /health` lists them from the moment the gateway starts, with what the last swap did.

## Fixed
- **A refused `/cors-proxy` POST now always gets its 403.** The gateway answered before reading the body, and on Windows that could reset the connection and lose the reply.

No chat text is kept, and responses reach the client byte for byte unchanged.
