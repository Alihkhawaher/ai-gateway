# v2.13.0 — 2026-11-12

## Added
- **Compacting early, without losing what the app cuts (`context_guard`, per endpoint, off by default).** Some apps only compact after the engine refuses the prompt, when the chat no longer fits and what they cut is lost. Cline 4.1.26 does this. With the guard on:
  - At 90% of the context window the gateway answers `context_length_exceeded` itself, while the whole chat still fits.
  - If the app then sends a compact request with a cut-down chat, the gateway puts the cut messages back, so the compaction reads everything.
  - If the app sends the same turn again with messages cut out, the gateway has the engine summarize them, adds the summary to that turn, and sends it as the first part of the reply so the app keeps it.
  - A different chat, a failed summary or anything unclear goes through as the app sent it, and the request after a "full" is never refused.
  - The chat is held in memory only, for that one follow-up request. **Compact early** in the endpoint dialog in Settings turns it on.
- **The log is kept on disk.** The console's log lines also go to `gateway.log` beside `config.json` (counts and names only, cut back at 5 MB), so they're still there after the console closes. `"log_file": false` turns it off.
