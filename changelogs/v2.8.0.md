# v2.8.0 — 2026-11-08

## Added
- **Tool call healing (`tool_heal`, per endpoint, off by default).** Local models sometimes write a tool call out as plain text, so the client shows it and nothing runs. The gateway now turns a complete written call into a real one, in the `<tool_call>` / `<function=name>` and JSON formats, streamed or not:
  - A call with a name the client doesn't have goes through under that name. Nothing runs, and the client tells the model which tools exist.
  - Tool names are never guessed, and parameter values are never edited.
  - Calls in a code fence or mentioned in a sentence stay text. So does anything incomplete or cut off.
  - A reply with nothing to repair keeps every character.
- **A command guard for accidents caused by errors.** Every call that would run is checked, healed or not, against rules for bash, PowerShell and cmd, using the shell the client's tool says it runs:
  - Deleting a root, home, drive or whole working folder, or a path that is only a variable or a PowerShell variable that was never set.
  - Paths damaged by escaping, such as lost backslashes or a `\n` decoded inside a path.
  - Cut-off replies, and broken arguments on command and file tools. A client's own repair can turn `rm -rf C:\Users\me` into `rm -rf C:Usersme`.
  - Unfiltered recursive deletes, redirects that empty a file, `git reset --hard` and similar, disks, shutdowns and commands that can't be read.
- **A stopped command never reaches the client.** You're asked if the client offers `ask_question`. Otherwise the model is told through a tool name that carries the rule, and the turn carries on. `allow_rules` lets rules through, and `guard: false` turns the checks off.
- **Calls healed and stopped appear in the console**, in the Live panel, Totals and Recent requests, and in the log. Counts and rule ids only: no reply text is kept.
- **A test suite of common tool call failures**, including bash, PowerShell and cmd commands that must be stopped and near misses that must still work.
- **Why a chat swap failed is kept and shown.** `GET /stats` and `/health` report the last failure (what was tried, the status and the engine's own words) and the console shows it.

## Fixed
- **A broken engine snapshot no longer causes a failed swap on every chat switch.** Strata 0.1.57 can get into a state where every save and restore answers `500 "conversation snapshot: invalid K/V extent"` and then reports an empty slot while it still holds the chat. After the first 500 the gateway leaves swapping off until the model is reloaded, or for 30 minutes, and says so in the console.
- **Restarting the gateway no longer loses track of the chat the engine holds.** Before, the first request after a restart could restore an older saved copy of the same chat, or another saved chat with the same opening, over what the engine already held. The newer part was then thrown away and read again. The session index now records which chat the engine holds, using hashes and counts only. A long chat the gateway can't identify is never restored over.
