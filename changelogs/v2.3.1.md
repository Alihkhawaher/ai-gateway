# v2.3.1 — 2026-08-21

## Fixed
- **Endpoint Edit/Remove buttons** — The settings screen's `✎ Edit` and `✕ Remove` buttons were non-functional because the code referenced the non-existent `DataTable.cursor_row_key` attribute. They now resolve the selected row via `get_row_at(cursor_row)`.
- **Model dropdown refresh** — `_update_model_select` used the removed `Select.add_option`/`clear` API. It now uses `Select.set_options` and is called on mount and after endpoint changes.
- **Model-index bounds check** — Opening Settings with a stale `model_index` (e.g., after models were removed) no longer crashes with an `IndexError`.
- **Settings screen crash** — Removed calls passing a second (unsupported) argument to `get_config`, which raised `TypeError` when opening Settings.
- **Thread-safe TUI logging** — Request log lines were written to the Textual `Log` widget directly from HTTP worker threads (a thread-safety violation). Lines are now queued (`queue.Queue`) and drained onto the UI thread.

## Changed
- **Port/address validation** — Invalid or out-of-range ports are reported with a toast instead of being silently ignored; changing port/address prompts a restart via a notification.
- **Endpoint removal confirmation** — Removing an endpoint now requires confirmation in a modal dialog.
- **Duplicate endpoint names** — Adding a duplicate endpoint name is rejected with an error toast instead of silently overwriting the existing endpoint.
- **Endpoint type auto-fill** — Selecting an endpoint type only auto-fills name/host when those fields are empty, preserving any values already typed.
- **Top-model fetch feedback** — Success/failure of the "fetch top intelligent models" operation is now reported in the TUI log.
